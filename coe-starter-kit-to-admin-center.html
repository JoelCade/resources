CoE Starter Kit → Power Platform Admin Center

What the Center of Excellence Starter Kit used to do, where that capability lives natively today, and what has no replacement at all. · July 2026

The one thing to remember: the CoE Starter Kit is unmaintained — not retired. It still works, and nothing is being switched off. But it receives no new features and its issues are no longer reviewed, while the native admin center capabilities keep advancing. Plan a migration; don’t panic into one.

1. What actually changed

Microsoft has confirmed that the Power Platform CoE Starter Kit is no longer actively maintained. Its core capabilities are now delivered natively in the Power Platform admin center through the Inventory, Usage, Monitor and Actions experiences.

  • The kit remains available for existing and new deployments.
  • It will not receive new capabilities or feature investment.
  • Issues are no longer reviewed or addressed. Suspected security vulnerabilities should go to the Microsoft Security Response Center rather than the project’s issue tracker.
  • Microsoft’s stated direction is to use the admin center as the central experience for governance, monitoring and insights.
Language matters here. “Unmaintained” is not the same as “deprecated”, “retired” or “end-of-life”. If you are briefing stakeholders, overstating this costs you credibility; understating it leaves your organization investing in a dead end. A working CoE deployment is not an emergency — it is a fork in the road that stops improving.

3. What the native experiences give you

Inventory GA

A unified, tenant-wide view of agents, apps, flows, environments and environment groups — including Copilot Studio agents, canvas, model-driven, code and vibe apps, and agent flows.

  • Roughly 15-minute freshness on create, update and delete — compared with the daily and fortnightly sync jobs the kit relied on.
  • Connector inventory (preview) shows which apps, flows and agents use a given connector or operation — which makes DLP scoping, premium-connector license audits and deprecation planning query-driven rather than manual.
  • Filter and sort on any attribute, customize columns, and export to Excel.
  • Programmatic access via the Power Platform inventory API, the Power Platform for Admins V2 connector, Azure Resource Graph (KQL) and the Power Platform CLI. This is the migration path for anyone who built custom reporting on the kit’s Dataverse tables.
Access gotcha. Inventory access is granted through Microsoft Entra roles (Global admin, Power Platform admin, Dynamics 365 admin, Global reader; the AI admin and AI reader roles are scoped to AI resources only). The built-in Power Platform role-based access control roles are not supported here — a common troubleshooting dead end.

Known gaps: classic chatbots are excluded; unpublished model-driven apps are not captured; the owner column for flows shows the original creator rather than the current owner; environment filters need the full environment name.

Usage Preview

Twenty-eight-day adoption trending — active users for Power Apps, run volume for Power Automate, and session counts for Copilot Studio agents — plus the highest-impact resources per product.

This is the least mature of the four. It is still a preview feature, still rolling out by region, and its agent-session counts use a 28-day lookback that will not reconcile with the Copilot area of the admin center. Do not retire your existing adoption reporting on the strength of this experience alone.

Monitor GA

Operational health derived from aggregated daily runtime event logs — health metrics, recommendations, alerts and downloadable logs.

  • Tenant-level analytics must be switched on, or there are no metrics, no logs and no recommendations at all.
  • Recommendations require a managed environment. Metrics and logs do not.
  • Metrics are not real-time, and unused resources never appear — the experience is driven by runtime activity.
  • Retention is short: logs for seven days, metrics for 28 days, with time-based metrics reported at the 75th percentile only.

If you need longer retention, custom traces or cross-resource correlation, Application Insights is still required — Monitor does not replace it.

Actions / Advisor GA

Recommendations across security, operational efficiency, licensing and capacity, and performance, with remediation available inline.

  • Full detail requires managed environments. Non-managed environments show only a summary; after enabling managed environments it can take up to 72 hours for full resource detail to appear.
  • Non-security recommendations can be snoozed for up to two months; security recommendations can be dismissed with a recorded reason. Both are reversible and auditable.
  • Action history tracks what was done and by whom; recommendations can be shared into Microsoft Teams, and a weekly summary card surfaces the top two.
  • Remediation can be automated through the Power Platform for Admins V2 connector — for example, emailing an app owner before an unused app is removed. This is also the supported export route.

4. The licensing dependency nobody mentions

Three of the four native experiences are materially degraded without Managed Environments:

ExperienceWithout managed environments
InventoryFull capability
UsageFull capability (preview caveats apply)
MonitorMetrics and logs only — no recommendations
ActionsSummary only — no resource detail and no remediation
This is the part to budget for. Managed Environments requires qualifying premium licensing for active usage in those environments. The CoE Starter Kit ran on a maker’s existing license — it was, in effect, the free-tier governance answer. So “just use the admin center instead” is not cost-neutral for a lightly-licensed estate: it is a licensing conversation wearing a governance hat. See the Power Platform Licensing & Managed Environments guide for the detail.

5. A sensible migration approach

  1. Lead with the correction, not the alarm. Unmaintained, not retired. Nothing has to be torn out this quarter.
  2. Map what you actually use. Most deployments only ever used inventory and adoption dashboards — both fully native today. If that describes you, this is a genuinely easy move.
  3. Name the real gaps early. ALM Accelerator, Innovation Backlog and the nurture assets need their own plan.
  4. Check the licensing dependency before promising Monitor and Actions capability you are not licensed to see.
  5. Check sovereign cloud availability. Inventory is not currently available in US Government (GCC, GCC High, DoD), 21Vianet (China) or air-gapped clouds — those tenants must stay on the kit for now.
  6. Point your report builders at the APIs, not the portal, if they had built custom reporting on the kit’s tables.
One more thing worth pre-empting: the admin center and the Microsoft 365 admin center will never agree on agent counts. Power Platform Inventory shows agents built on Power Platform, including drafts. The Microsoft 365 admin center shows agents available in the tenant — first-party, third-party and org-created, published only. Both numbers are correct in their own context. Clarify which question is being asked before anyone reports a figure upward.
