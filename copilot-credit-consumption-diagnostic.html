Why Is a Non-Autonomous Agent Consuming Copilot Credits?

A structured walkthrough for diagnosing credit consumption on an agent that is used only by Microsoft 365 Copilot licensed employees. Compiled from public Microsoft documentation · August 2026.

The one thing to remember: the Microsoft 365 Copilot inclusion does not follow the agent. It follows the identity. If the platform cannot see an authenticated Microsoft 365 Copilot licensed user at the moment of the call, it meters the call at the standard rate, no matter how simple, internal, or non-autonomous the agent is.

The rule that governs everything

Microsoft's billing documentation grants a "No charge" column against every credit rate for usage by a Microsoft 365 Copilot licensed user. That column is real, but it is conditional. The footnote behind it sets out four conditions, and all four must hold at once:

  1. Employee-facing (B2E) scenario. The inclusion covers business-to-employee usage. Customer-facing and public-facing traffic is outside it entirely.
  2. The user is licensed with Microsoft 365 Copilot.
  3. The agent operates using that authenticated user's identity. This is the condition that quietly fails most often.
  4. Usage stays within fair use limits. Microsoft explicitly reserves the right to update these limits as usage patterns emerge.

Break any one condition and the interaction bills at the standard published rate:

Agent featureStandard rateUsed by an M365 Copilot licensed user
Classic answer1 creditNo charge
Generative answer2 creditsNo charge
Agent action5 creditsNo charge (except computer use)
Tenant graph grounding10 creditsNo charge
Agent flow actions, per 100 actions13 creditsNo charge (agent-invoked trigger only)
Text and generative AI tools (basic / standard / premium)1 / 15 / 100 creditsNo charge
Content processing tools, per page8 creditsNo charge
The framing that defuses the conversation: agents are included with Microsoft 365 Copilot, not free. The inclusion was scoped to employees using agents under their own identity. It was never scoped to cover anonymous channels, non-agent-triggered automation, computer use, voice minutes, or maker build activity. Establishing that distinction early prevents a second round of surprise later.

The twelve root causes

IDRoot causeWhat you see in the dataWhere to verify and how to fix
RC-1 Published to a non-B2E channel. Custom website, demo site, Direct Line, SMS, or a public portal. Employees arriving through those channels are anonymous, so no license is detectable. Steady burn that does not track licensed headcount. Classic and generative answers dominate the cost distribution. Copilot Studio > Channels. Look for a demo website left enabled after a pilot. Disable unused channels and route employees through Teams or Microsoft 365 Copilot.
RC-2 Identity is not flowing. Authentication set to "No authentication" or to a manual / custom provider rather than "Authenticate with Microsoft". The agent runs, but not as the licensed user, so condition 3 fails. Credits accrue even from Teams usage by users you know are licensed. Copilot Studio > Settings > Security > Authentication. Set "Authenticate with Microsoft", configure Entra ID single sign-on for the Teams channel, republish, then re-baseline over 48 hours.
RC-3 Mixed license population. A single unlicensed user meters at the full rate. Microsoft's own worked example: 50 licensed plus 100 unlicensed users equals 4,800 credits per day, driven entirely by the 100. Burn scales with total headcount, not with licensed headcount. Cross-reference the agent's sharing scope in Copilot Studio against Microsoft 365 Copilot license assignment in the Microsoft 365 admin center. Gate sharing to a licensed-only security group, or budget for the metered tail deliberately.
RC-4 Agent flow trigger mismatch. The inclusion covers only the "When an agent calls the flow" trigger. Scheduled, Dataverse row-created, HTTP request, and every other trigger bills at the standard rate regardless of who the user is. The "Agent flow actions" line is non-zero in the PPAC consumption grid. PPAC > Licensing > Copilot Studio > Environments > select the environment > Copilot credit consumption details. Re-plumb the flow to be agent-invoked, or move the work to a Power Automate cloud flow, which uses Power Automate licensing and consumes no Copilot Credits at all.
RC-5 Session initialization and proactive greeting. Microsoft states that if the agent is triggered to be ready for a conversation, it consumes credits as a classic answer, whether or not a greeting is sent and whether or not the user ever replies. High billed volume against a low engaged-conversation count. Compare billed credits with engaged conversations on the Analytics page. Remove auto-greet on page load and stop auto-instantiating the agent when an app or portal loads. This is the abandoned-session tax.
RC-6 Computer Use Agents. Explicitly not included in the Microsoft 365 Copilot license, and billed at the agent action rate. Agent actions line unexpectedly high at 5 credits per action. Review the tools attached to the agent for computer use. This is expected behavior, so budget for it or remove the capability.
RC-7 Voice channel. Metered per minute at 10 (classic voice), 35 (GenAI voice), or 75 (premium GenAI voice) credits. Core agent activity is bundled into that minute rate. Burn tracks call minutes rather than message counts. Check the voice configuration in the channels list. Expected behavior, and not a B2E Copilot-included scenario.
RC-8 Preview features. Capabilities in preview bill at the published rate and count against purchased capacity. There is no preview discount. A new line item appears shortly after someone enables something new. Correlate the consumption trend against your change log, then set expectations or disable the preview feature.
RC-9 Build-time billing on the GitHub Copilot harness. Unlike the standard harness, which bills after publish, this harness charges from the moment building starts: natural-language authoring, preview and test, and generating agent evaluations all consume credits. Credits burning on an agent that was never published. Confirm which harness the agent runs on. Expected behavior, so budget maker activity separately from runtime. Note the contrast: on the standard harness the embedded test chat does not bill.
RC-10 Bring your own model. Azure AI Foundry and other customer-supplied models are billed separately and sit outside the Copilot Credits rate table entirely. Azure consumption appears alongside credit consumption. Check the model configuration on the agent. Separate meter, separate budget line, expected behavior.
RC-11 Generative answer nuance. Generative answers incur charges unless the agent was created in Agent Builder in Microsoft 365 and the response does not use tenant graph grounding. Generative answer charges on what looks like a simple Microsoft 365 agent. Establish where the agent was authored and whether tenant graph grounding is on. Switch grounding off per agent where it is not earning its place: it is a 10-credit line item on its own.
RC-12 Copilot Studio for Teams versus standalone. Agents created inside the Teams environment never consume credits, for anyone. Agents built in standalone Copilot Studio and then deployed to the Teams channel do consume, though licensed users are not billed. Two apparently similar agents with wildly different bills. Check where each agent was authored. This explains the apparent inconsistency and is not a defect.
Where to start: in practice RC-1 (a demo website left switched on after a pilot) and RC-4 (agent flow trigger mismatch) account for the large majority of these conversations, with RC-5 (auto-greet on load) as the quiet third. Test those three before going deeper.

Running the diagnosis live

1

Establish the shape of the spend in PPAC

Power Platform admin center > Licensing > Copilot Studio > Summary for tenant-level totals, then the Environments tab and the Copilot credit consumption details grid for the environment in question. Isolate which environment and which feature line is burning before forming any theory.

Consumption data aggregates daily and can lag. Read the "Last updated" tooltip before drawing conclusions, and never troubleshoot against the last sixty minutes.

2

Isolate the agent in Copilot Studio analytics

Open the agent, go to Analytics, and read the Billing trend and Cost distribution charts. Cost distribution tells you the category of the burn, which maps directly onto the root cause table:

  • Classic answers high, engaged conversations low, points to RC-5
  • Agent flow actions non-zero, points to RC-4
  • Agent actions high, points to RC-6
  • Tenant graph grounding high, points to RC-11
  • Generative answers high alongside anonymous traffic, points to RC-1 or RC-2
3

Correlate against the trend line

Find the date the burn started and match it to a publish event, a channel enablement, a sharing or security-group change, a licensing change, or a preview feature toggle. Unexplained consumption almost always has a birthday, and it is almost always a configuration change rather than a mystery.

4

Prove the fix, one variable at a time

Change one thing, republish, and hold a 48-hour observation window before changing anything else. Multiple simultaneous changes produce a result nobody can interpret, which is how these investigations end up running for a month.

Outside the inclusion
  • Computer Use Agents
  • Agent flows on any trigger other than "When an agent calls the flow"
  • Voice minutes
Outside the inclusion
  • Bring-your-own-model consumption, billed separately by Azure AI Foundry
  • Any unauthenticated or customer-facing traffic
  • GitHub Copilot harness build, test, and evaluation activity

Preventive controls

Cap the blast radius per agent

PPAC > Licensing > Copilot Studio > Manage Agents lets you set a monthly consumption limit on an individual agent. This is the single most effective control, because it contains a misconfigured agent before tenant-level enforcement affects everything else.

Understand enforcement before you meet it

Tenant enforcement triggers at 125% of prepaid capacity and it disables custom agents. In-flight conversations complete, then users see "There is a billing issue" or "This agent is currently unavailable. It has reached its usage limit." Administrators receive an email and a notification in PPAC.

Agent flow enforcement is separate and behaves differently: when prepaid capacity is exhausted it blocks new agent flow runs while leaving the agent functional for classic answers, generative answers, and agent actions. Runs already in progress complete normally.

Allocate capacity per environment

Environments with an explicit allocation are shielded when the shared tenant pool goes into overage. Environments with no allocation draw from the shared pool and are the first to be enforced. Capacity does not roll over: credits reset on the first of the month, not on the license anniversary.

Use pay-as-you-go as an availability control

A pay-as-you-go billing plan on a business-critical environment means overage bills to Azure instead of disabling the agent. Frame this to the customer as a resilience decision, not purely a billing one.

Forecast before you build

The Copilot Studio agent usage estimator models expected credit volume from agent type, traffic, orchestration approach, knowledge sources, and tools. Running it during design is far cheaper than running this diagnostic later.

Handling the hard questions

"We were told agents are free with Microsoft 365 Copilot."

Included, not free, and the inclusion is scoped. It covers employee-facing agents used by a licensed user operating under that user's own identity. Anonymous channels, non-agent-triggered automation, computer use, voice minutes, and maker build activity were never inside it.

"Nothing changed on our side."

Something changed on a date. Pull the billing trend, find the inflection point, and work backwards to a publish, a share, a channel toggle, or a licensing change. The burn has a birthday in essentially every case.

"Can we just turn credits off?"

No, and you would not want to. At 125% of capacity agents are disabled outright, which is a production outage rather than a cost saving. Use per-agent caps for control and pay-as-you-go for resilience.

"Our agent is not autonomous, so why is anything metered at all?"

Autonomy is not the billing boundary. Identity is. A fully interactive, human-initiated agent still meters every turn where the platform cannot resolve an authenticated Microsoft 365 Copilot licensed user, and it meters every agent flow that starts from a trigger other than the agent itself.

Diagnostic checklist

Configuration

  • Channel list reviewed, demo and website channels disabled unless deliberately in scope
  • Authentication set to "Authenticate with Microsoft"
  • Entra ID single sign-on configured for the Teams channel
  • Agent sharing scoped to a security group whose members are all licensed
  • Auto-greet and auto-instantiation on load removed
  • Every agent flow confirmed to use the "When an agent calls the flow" trigger, or moved to a Power Automate cloud flow
  • Tenant graph grounding switched off where it is not adding measurable value
  • Computer use, voice, and bring-your-own-model usage identified and budgeted separately

Measurement

  • PPAC consumption grid reviewed at environment level, by feature line
  • Per-agent cost distribution reviewed in Copilot Studio analytics
  • Billed credits compared against engaged conversations
  • Consumption inflection point correlated to a specific configuration change date
  • One variable changed, then a 48-hour observation window held before the next change

Governance

  • Per-agent monthly consumption limits set in PPAC
  • Capacity explicitly allocated to business-critical environments
  • Pay-as-you-go considered for environments where an outage is unacceptable
  • Administrators know what the 125% enforcement message looks like before users report it
  • New agents forecast with the usage estimator before build starts
