AI Builder to Copilot Credits Sizing Calculator

Model what an existing AI Builder workload costs once it is metered in Copilot Credits — per capability, with the real published rates. Compiled from public Microsoft documentation · August 2026.

The one thing to remember: there is no conversion rate. Microsoft does not exchange AI Builder credits for Copilot Credits, and no entitlement transfers from one currency into the other. The two currencies price the same capabilities at independently published rates, so the only meaningful question is what a given workload costs in each. That is what this page calculates.

How to use it

Everything on this page runs in the browser. Nothing is uploaded, stored, or transmitted, so it is safe to run against real consumption figures.

1. Pull the real numbers. In the Power Automate portal, open AI Builder → Activity and filter to a representative month. That page now reports consumption in both currencies, broken down by capability, which is exactly the shape this calculator expects.

2. Enter monthly volume per capability in the units the rate card publishes — thousands of tokens for prompts, pages for document work, thousands of characters for text analysis, images for vision. Leave a row at zero if it is not in use.

3. Set the capacity basis and check the price assumptions. Tell the calculator whether the existing AI Builder capacity was purchased as a capacity add-on or arrived seeded with Power Platform licensing, because it changes what the result means. The price defaults reflect public list pricing; if a negotiated rate applies, substitute it, since the discount moves the answer materially.

4. Read the multiplier column, not just the total. The total tells you the size of the change. The multiplier tells you which workload is driving it. On an entitlement basis the multiplier is suppressed, because there is no paid baseline to divide by.

Price assumptions

Both currencies are converted to money before comparison, because a raw credit-to-credit ratio is misleading — a credit is not the same size in each currency. Set the capacity basis first, then adjust the prices to match how the customer actually buys.

How is AI Builder capacity held today?

Seeded credits arrive included with Power Apps, Power Automate or Dynamics 365 licensing and carry no separate line item. If that is the case, there is no AI Builder contract to price against and no discount to apply.

Reading the result

Read the delta in dollars first, then use the multiplier to find out where it came from. At list pricing a Copilot Credit costs roughly twenty times what an AI Builder credit costs, so a capability only holds its value if its rate ratio is also about twenty to one. Most capabilities land close enough that the change is modest. A small number do not, and those are what the multiplier column is for.

multiplier = (Copilot Credit rate x Copilot Credit price) / (AI Builder rate x AI Builder credit price) below 1.0 cheaper after the move about 1.0 cost neutral above 1.0 more expensive after the move

At list prices the capabilities sort into three clear groups.

GroupCapabilitiesMultiplier
Improves or holds Text recognition (OCR), simple text analysis 0.7x to 1.0x
Modest increase Prompts on all three model tiers, text translation, advanced text analysis, custom document processing 1.1x to 1.6x
Materially worse Receipt, invoice, identity and contract processing (5x); object detection (20x) 5x to 20x
Object detection is the outlier that decides most business cases. It is the one capability rated identically in both currencies, at 8 credits per image. Because the currencies are not priced identically, an identical rate means a twenty times increase at list — but only for that capability, and only in proportion to how much of it a workload actually runs. Low-volume image classification stays small in absolute terms. High-volume image classification is the case that needs examining before, not after, the pricing conversation.
On an entitlement basis the multiplier does not apply. Where the existing AI Builder capacity arrived seeded with licensing rather than purchased, the incremental cost today is zero and there is no denominator to divide by. Set the capacity basis to seeded with licensing and the calculator suppresses the multiplier and reports the Copilot Credits total as net-new spend instead. The honest framing in that case is not that a price went up, but that capacity which came included now meters — and that the seeded allocation ends on November 1, 2026 regardless.

Gotchas that change the answer

Timing

Seeded credits stop on November 1, 2026

Credits that arrive seeded with Power Apps, Power Automate or Dynamics 365 licensing simply end. There is no transition grant and no replacement allocation. Purchased capacity add-ons continue to the end of their term, but they cannot be renewed or expanded after that date, so an add-on is a runway extension rather than a long-term answer.

Scope

The two currencies are not interchangeable

Inside Power Apps and Power Automate, an environment draws down AI Builder credits first and falls back to Copilot Credits. Inside Copilot Studio, including agent flows, only Copilot Credits are accepted. An existing AI Builder balance therefore does nothing at all for agent work, which is usually the thing a customer is planning to build next.

Operations

Consumption reporting lags by five days or more

Usage is computed daily but can be delayed several days. During that window the platform believes there is headroom and keeps accepting work. When the calculation catches up, overage is not billed — runs are blocked instead. This is an availability risk rather than a cost risk, and it deserves a monitoring threshold well below 100 percent of entitlement.

Billing

Connector metering is additive

Every AI Builder action is a premium connector action. Under pay-as-you-go the flow run is metered on its own meter in addition to the credits the AI capability consumes. Modeling only the credit line understates the true cost of a high-frequency flow.

Lever

Bring your own model changes the math

When a text or generative AI tool runs against a customer-supplied model, no Copilot Credits are charged for the processing itself; only the surrounding agent action is metered, and token cost moves to the model host. For a high-volume prompt workload this is the single largest available lever, and it is worth modeling as a separate scenario.

Volume

Document processing is charged flat per page

Content processing bills the same 8 credits per page or image regardless of how much content the page holds. A fifty page contract is four hundred credits. Workloads that process long documents should be sized on page count, never on document count.

Discovery checklist

Run this before quoting any number. The first item alone often changes the recommendation entirely.

  • Establish where the existing credits came from. Seeded entitlement and a purchased add-on have very different timelines.
  • Export a representative month from the AI Builder Activity page, broken down by capability rather than in total.
  • Confirm which capabilities are genuinely in production against which were trials that never retired.
  • Identify any object detection or prebuilt document processing usage first, since those dominate the delta.
  • Check whether the workload will be rebuilt as an agent, because that removes the AI Builder option entirely.
  • Confirm contracted pricing rather than list, in both currencies — or establish that no AI Builder contract exists, which is itself the answer.
  • Set a consumption alert well below the entitlement ceiling to absorb the reporting lag.
  • Decide on add-on renewal timing ahead of the November 1, 2026 boundary.
