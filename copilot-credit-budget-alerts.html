Budget & Cost Alert Options for Copilot Credits

Every control available for capping and alerting on Copilot Credit spend, which console owns it, and which ones actually stop consumption rather than just sending an email. Compiled from public Microsoft documentation · September 2026

The one thing to remember: there is no single currency-denominated budget object in the Power Platform admin center. Credit governance is split across three separate consoles, and most organizations configure one and assume they are covered. Alerts and caps are also different things — most of these controls only notify.

1. The three consoles

All three draw on the same Copilot Credit pool. Capacity allocated to Power Platform environments reduces the prepaid credits available to Microsoft 365 usage-based experiences such as Cowork and Work IQ, and vice versa. If you set limits in one console without looking at the others, you will misjudge what is actually available.

1

Power Platform admin center

Environment capacity allocation, overage behavior, and per-agent monthly limits with a hard stop. Also usage-metric alert rules under Monitor.

2

Microsoft 365 admin center

Cost Management spending policies. Monthly and per-user credit caps scoped to Entra groups, with threshold email alerts and a credit request workflow.

3

Azure Cost Management

Currency budgets and alerts against the Azure subscription behind a pay-as-you-go billing plan. Actual and forecasted, with automation hooks.

2. Options at a glance

Control Console Effect Notes
Agent monthly limit with Stop usage PPAC Hard stop Notification threshold plus optional auto-disable. Works on prepaid and pay-as-you-go. The only true ceiling on the PPAC side.
Environment allocation with tenant draw turned off PPAC Caps prepaid Caps prepaid consumption only. Does not block a linked pay-as-you-go plan, so spend continues through Azure.
Environment group rule for tenant pool draw PPAC Caps prepaid Applies the setting across a group. Makes the environment-level setting read-only, including for programmatic requests.
Monitor alert rules PPAC Notify only Usage metrics, not currency. Managed Environments only, 24-hour evaluation, 50 active rules per tenant.
Spending policies M365 Hard cap Monthly and per-user caps, Entra group scoping, threshold emails, credit requests, per-policy billing method.

Budget alert into an Action Group Azure Notify and automate Routes the alert to a Logic App or Automation runbook so it can trigger a response rather than an inbox.
Programmatic via Power Platform API or SDK API Custom Apply allocations at scale and feed consumption data into alerting you already run.

3. Power Platform admin center

Where capacity is allocated, and where the only per-workload hard stop lives.

Agent monthly limit, notification, and Stop usage

Licensing › Products › Copilot Studio › Manage Agents › Set limit
  • Set a monthly Copilot Credit limit for an individual agent
  • Configure a notification threshold, so tenant and environment admins are alerted as usage approaches it
  • Turn on Stop usage to automatically disable the agent when it reaches the limit
  • Agent status reports as Within limit, Nearing limit, or Over limit
  • Available whether the environment uses prepaid capacity or pay-as-you-go. On prepaid, the agent must still stay within the allocated pool

Environment allocation and overage behavior

Licensing › Products › Copilot Studio › Manage Copilot Credits
  • Allocate a credit count to a specific environment
  • Under Capacity overages, clear Draw from the available capacity in my tenant to cap the environment at its allocation
  • For eligible environments, tenant draw is selected by default when no allocation configuration exists
  • At scale, use the environment groups rule Cost controls — Draw from tenant credit pool. Publishing it makes the environment-level setting read-only, and programmatic requests cannot override it
An allocation is not a boundary if the environment can still draw from tenant capacity or bill to a pay-as-you-go plan. Both paths need closing before you can call it a cap.

Monitor alert rules

Monitor › Alerts › + Alert rule
  • Custom rules across Power Apps, Power Automate, and Copilot Studio metrics, with your own threshold, operator, and severity
  • Email to you plus up to four recipients, sent from PowerPlat-noreply@microsoft.com
  • These are usage-metric alerts, not currency. Agent session counts work as a leading indicator of credit burn
  • Managed Environments only. Evaluated every 24 hours, not in real time. Limit of 50 active rules per tenant
  • Microsoft's predefined alerts are on by default, cannot be edited, and send no email. You have to open Monitor to see them

Monitoring and reporting

  • Summary, Environments, and Agents tabs give tenant, environment, and agent views
  • Downloadable consumption report, with daily data for three months and monthly data for twelve
  • Review environment and agent together. A tenant-level total hides a single runaway agent
  • Costs are not attributed to individual makers or end users, because billing happens at environment and agent level. Control who can build and run agents through permissions instead

4. Microsoft 365 admin center — Cost Management

The more capable budget surface, and the one most often missed. It governs the same Copilot Credit pool as the Power Platform allocations above.

Copilot › Cost Management › Configuration
  • Monthly spending limit per policy, either unlimited or capped at a set number of credits
  • Per-user limits, so a single person cannot drain the whole pool
  • Group scoping to all users or to specific Entra security groups, which enables genuine departmental budgets. Individual users are supported only through security groups
  • Alerts: choose the stakeholders and a threshold. Emails begin at the threshold and repeat weekly until the month resets or you adjust the limit
  • Credit request workflow, so users who hit a limit can request more rather than simply being blocked
  • Per-policy billing method, which enables departmental chargeback
  • The dashboard Top actions area surfaces policies and users approaching their limits
  • Policies always consume prepaid credits first, whether from capacity packs or pre-purchase plans, before falling through to pay-as-you-go
Two things to plan around. Roles: AI Administrator and License Administrator can create policies and manage limits and alerts, but cannot set or change the billing method. And a policy's billing method is fixed once created, so changing it means deleting the policy and creating a new one.

Note that spending policies are limit-based. They do not allocate or reserve credits, which is a meaningful difference from environment capacity allocation in the Power Platform admin center. Deleting a policy removes the limit, not any capacity.

5. Azure Cost Management

The only place you get a budget denominated in currency. It applies to pay-as-you-go across Power Apps and Power Automate meters too, not just Copilot Studio.

  • Create budgets and alerts on the Power Platform account resource associated with the billing plan
  • Forecasted alerts fire when projected spend is trending to breach the threshold, which gives advance warning rather than a post-mortem
  • Cost anomaly alerts catch unexpected movement outside your configured thresholds
  • Route budget alerts to an Action Group and on to a Logic App or Automation runbook, so the alert triggers an actual response
Azure budgets never stop Copilot Studio consumption. They notify. Pair every pay-as-you-go plan with an agent-level Stop usage limit, or there is no ceiling at all.

6. Suggested minimum configuration

  1. Allocate credits per environment and turn off draw from tenant capacity for anything not explicitly funded.
  2. Set agent monthly limits with Stop usage on anything customer-facing, autonomous, or newly launched.
  3. Stand up Microsoft 365 spending policies with per-user caps and threshold alerts, scoped to the groups that match how you actually budget.
  4. Configure Azure budgets with forecasted alerts on every pay-as-you-go billing plan.
  5. Name an accountable owner per environment and per billing plan who genuinely receives and acts on the alerts.
  6. Document the request path, so makers know how to ask for more capacity when the need is legitimate.

7. Timing note

Developer and trial environments moved to usage-based billing on 1 September 2026. If limits and alerts were not configured beforehand, consumption that was previously non-billed is now generating charges. The Non-billed Copilot Credits information in Manage Agents and in the downloadable consumption report gives a directional view of that exposure, though it is not a billing estimate or a guarantee of future cost.
