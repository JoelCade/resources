Microsoft Copilot Studio · Cost Optimization Playbook

Evaluating & Optimizing Copilot Credit Consumption in Production

A four-phase playbook — measure, diagnose, optimize, govern — for teams running Copilot Studio agents at scale. Compiled from public Microsoft documentation · Updated August 2026.

The one thing to remember: Copilot Credits are billed per event, not per conversation — and events stack on a single user turn. The same question answered by a classic topic costs 1 credit; answered by generative orchestration with graph grounding and two tool calls it can cost 20+ credits. Optimization is almost never about "using the agent less" — it's about routing each intent to the cheapest mechanism that still answers it correctly.

Which harness are you on? (read this first)

Copilot Studio is a multi-harness platform. A harness is the runtime that sits between what you author and the model that reasons: it decides when to call the model, what to send it, and which tools to invoke. Since August 3, 2026 there are three, chosen when the agent is created, and the harness determines which billing model applies. Everything else on this page — the rate card, the stacking rule, the ten cost drivers, the optimization levers — describes the standard and Copilot chat harnesses. It does not describe the GitHub Copilot harness.

HarnessBest forHow it bills
StandardRule-based agents, structured conversations, agent flowsThe credit rate card below, or included in a Microsoft 365 Copilot user subscription license
Copilot chatExtending Microsoft 365 Copilot Chat with enterprise knowledgeConsumption, or included in a Microsoft 365 Copilot user subscription license
GitHub CopilotReasoning-heavy, multi-step business processesUsage-based Copilot Credits. Not the rate card. Not included in a Microsoft 365 Copilot license.
Three assumptions that hold everywhere else on this page break on the GitHub Copilot harness.
  • It is not the rate card. Consumption is usage-based, measured against the work performed rather than a published per-event price. Microsoft states credits are charged for large language model tokens, for tools (including knowledge and MCP servers), and for the harness itself — so there is no per-event table to optimize against in the way Phase 3 describes.
  • Billing starts when you start building, not when you publish. This is the reversal that catches teams out. On the standard harness, cost begins at publish. On the GitHub Copilot harness, creating a solution with natural language, previewing and testing the agent, and generating and running agent evaluations all consume credits — on an agent that may never ship.
  • There is no Microsoft 365 Copilot license inclusion. The "licensed employee-facing user costs nothing" logic does not carry over. Usage is billed regardless of what the user is licensed for.

Two practical consequences. First, identify the harness before you diagnose anything — credits burning against an agent that was never published is expected behavior on the GitHub Copilot harness and a genuine defect on the standard harness, and the remedy is completely different. Second, maker activity becomes a budget line of its own. A team doing heavy iteration or running large evaluation suites is generating real consumption before a single end user arrives, so forecast build-phase spend separately from runtime spend.

What a GitHub Copilot harness task actually costs

There is no per-event rate card, but Microsoft publishes planning bands in the Copilot Credits Guide. Runtime cost is driven by four factors — the models chosen for the task, the runtime orchestration that keeps work moving across steps, the context retrieved to ground the work, and the tools invoked to act on it.

Runtime bandShape of the workEst. credits per task
LightFew sources, light reasoning, one or fewer outputs. For example: check an email, verify a workbook, post a status summary.100 – 300
MediumMany sources across varying timeframes, structured reasoning, two or more deliverables.300 – 500
HeavyBroad aggregation and deep reasoning over long timeframes, many outputs.> 500

Build-phase consumption has its own bands. Natural language authoring is estimated by conversation turns, meaning the number of messages you send in a single creation session — more turns generally means a more complex agent needing iterative refinement. Preview and evaluation consume credits at the same rate as runtime, which is what makes a large evaluation suite a real recurring line item rather than a one-off.

Manual configuration is free. No credits are consumed for work performed in the Build and Monitor tabs. Only the model-powered maker experiences meter.

Do this arithmetic before an account starts building. A light task at 100 to 300 credits is 50 to 150 times the cost of a generative answer on the standard harness, which bills 2 credits. The capability difference is real and so is the cost difference. These are rough planning estimates published by Microsoft, not commitments — actual consumption varies with workflow and usage pattern, so treat them as a starting point for your own modeling rather than a quote.
Do not reuse these bands for Copilot Cowork. Cowork publishes bands with word-for-word identical descriptions but different figures: light 100 to 300, medium 300 to 700, heavy above 700. Quoting one workload's numbers for the other misprices the medium band by up to 40%. Check which product you are estimating.

Work IQ APIs bill separately, and can cut cost

If your agents call the Work IQ APIs, that consumption is its own line and is not covered by a Microsoft 365 Copilot license. The Work IQ Tools API is a flat 0.1 credit per API call for actions and tools. The Work IQ Chat and Context APIs are variable, billing query-style consumption for grounding, retrieval, and reasoning.

Two clarifications worth holding on to. Work IQ accessed natively inside Microsoft 365 Copilot carries no incremental charge — that covers Copilot Chat, the in-app experiences in Word, Excel and PowerPoint, and the included agents such as Researcher, Analyst and Facilitator. The charges apply only when an agent or AI solution calls the APIs directly. And there is a genuine optimization angle here: Microsoft states that shifting AI processing into the Work IQ runtime cuts the tokens needed for context retrieval and tool use by up to 80%, reducing credit consumption in agentic solutions. Treat that as a vendor figure to validate against your own workload, not a guarantee.

Existing agents are unaffected. The standard and Copilot chat harnesses are unchanged by the August launch, agents built on them keep running, new agents can still be created on them, and license inclusion continues. There is also no automatic migration between harnesses — an agent created on one cannot be transferred to another, so harness choice is effectively a rebuild decision rather than a setting.

Phase 0 — Understand the billing model

Applies to the standard and Copilot chat harnesses. For the GitHub Copilot harness, see the section above.

As of September 1, 2025, the common currency for agents changed from Copilot Studio messages to Copilot Credits. Microsoft states there was no change to the quantity per prepaid pack or to the pay-as-you-go rate at the time of the transition — but the model now exposes event-level granularity rather than the older "billed session" abstraction.

The credit rate card

These rates apply to the language models Copilot Studio provides. Bring-your-own models hosted in Azure AI Foundry are billed separately by Foundry; Copilot Studio charges only the agent-action rate to invoke them.

Event typeCreditsBilled unitWhat triggers it
Classic answer1per responseA static, author-written response from a topic. No model call.
Generative answer2per responseAn AI-generated response grounded in connected knowledge.
Agent action5per actionEach tool/connector call, trigger, topic transition, deep-reasoning step, or Computer Use step.
Content processing8per page / imageDocument and image processing tools.
Tenant graph grounding10per messageGrounding in Microsoft 365 tenant data — charged on top of the answer.
Agent flow actions13per 100 actionsIndividual actions executed inside an agent flow.
AI tools — basic1per 10 responses≈ 0.1 credits per 1K tokens. OCR, sentiment, key phrases, simple text.
AI tools — standard15per 10 responses≈ 1.5 credits per 1K tokens. General-purpose prompts.
AI tools — premium / reasoning100per 10 responses≈ 10 credits per 1K tokens. Deep reasoning models.
Voice — classic orchestration10per minuteVoice channel; core agent activity included in the rate.
Voice — generative35per minuteVoice channel with generative orchestration.
Voice — premium generative75per minuteVoice channel with premium models.
The stacking rule is the whole game. Multiple event types bill simultaneously on one user turn. Microsoft's own example: a tenant-graph-grounded response is 10 (graph) + 2 (generative answer) = 12 credits for a single reply. Add one tool call (+5) and a standard prompt action over 3K tokens (+4.5) and that turn is 21+ credits. Reasoning models add their token cost on top of the base feature rate: a 2,000-token reasoning generative answer is 2 + 20 = 22 credits.

How credits are purchased

Prepaid capacity packs

Monthly pool, no rollover

  • Bought in the Microsoft 365 admin center; pooled at tenant level.
  • Can be allocated to specific environments in PPAC.
  • Resets monthly — unused credits do not roll over.
  • Subject to enforcement throttling when exhausted.
Pay-as-you-go

$0.01 per credit, billed to Azure

  • Billing policy in PPAC links an environment to an Azure subscription.
  • No upfront commitment; billed monthly in arrears.
  • Not subject to enforcement throttling — business continuity is maintained.
  • Charges land on a Power Platform Account resource in Azure.

A one-year pay-upfront option, the Copilot Credit Pre-Purchase Plan (P3), also exists. Note the split provisioning surface that catches admins out: the pay-as-you-go meter is provisioned in the Power Platform admin center, while the Pre-Purchase Plan is provisioned in the Azure portal. P3 credits are deducted automatically from the purchased balance, and if usage exceeds it you either buy more or fall back to pay-as-you-go. Unused P3 credits expire at the end of the annual term, so oversizing a tier to reach a bigger discount can cost more than it saves.

Both purchasing constructs decrement the Microsoft Azure Consumption Commitment. The Copilot Credits Guide states that pay-as-you-go and the Pre-Purchase Plan each draw down MACC. If your organization carries an Azure commitment, factor that in before treating credits as net-new spend — it often changes the funding conversation entirely.
Volume matters at scale. The public Copilot Credits Guide publishes a tiered discount on the Copilot Credit pre-purchase plan. If you are modeling a large deployment, the effective rate is not a flat $0.01 — check which tier your annual volume lands in before you build a business case on the headline number.

What is not billed — check this before optimizing anything

  • Testing in the Copilot Studio test chat panel, testing an agent flow from the designer, testing a prompt in prompt builder, and training an AI Builder custom model are all free.
  • End users talking to a published agent do not need a license.
  • For authenticated, employee-facing scenarios where the user holds a Microsoft 365 Copilot license, classic answers, generative answers, tenant graph grounding, agent actions, AI tools, content processing, and agent flows using the "when an agent calls the flow" trigger are all zero-rated.
Two exceptions people get wrong. Computer Use is not zero-rated for Microsoft 365 Copilot licensed users — it bills at the standard agent-action rate regardless. And agent flows are only zero-rated when triggered by "when an agent calls the flow"; other triggers bill normally. Zero-rating also requires the agent to run under the user's authenticated identity, and Microsoft applies fair-usage limits it reserves the right to change.

Phase 1 — Measure: where the numbers actually live

You cannot optimize what you are not reading weekly. There are four distinct surfaces, and each answers a different question.

1

Power Platform admin center — the governance hub

PPAC → Licensing → Copilot Studio. This is the primary source of truth for spend.

  • Summary tab: prepaid capacity purchased / assigned / consumed, month-to-date PAYG credits, capacity split between Copilot Studio and Microsoft 365 Copilot Chat, a daily consumption trend, and top environments by credit usage.
  • Environments tab: per-environment consumption, plus a Copilot credit consumption details grid that breaks spend down by agent, by product, and by feature name — this is where you find out that graph grounding, not your tools, is eating the budget. Agent flow actions are listed separately.
  • Manage agents page: search every agent in the tenant, see month-to-date billed credits per agent, and read status indicators (within limit / nearing limit / over limit).

Data availability: daily figures for the current month plus the previous two full months, and monthly figures for the past 12 months.

2

Copilot Studio analytics — the behavioral "why"

Copilot Studio → your agent → Analytics. PPAC tells you what you spent; analytics tells you what the agent was doing.

  • Engagement, resolution, escalation and abandon rates, CSAT, and active users. Abandon rate paired with high credit spend is the classic waste signal.
  • Autonomous analytics for trigger-based agents: trigger receipt through action completion.
  • Topic analytics (classic mode) or themes (generative orchestration) to see which intents dominate volume.
  • Session transcript export as CSV — session ID, outcome, turn count, transcript, topic, channel, CSAT.

Analytics data is retained up to 360 days; session transcripts are available for roughly the last 28–29 days, so export before the window closes if you want a baseline. A conversation times out after 30 minutes of inactivity (3 minutes on telephony).

3

Azure Cost Management — the finance view for PAYG

All pay-as-you-go charges land on the Power Platform Account resource created in the linked Azure subscription. Put it in a dedicated resource group and tag it so cost can be allocated by team or business unit, then use budgets and cost alerts against it like any other Azure resource.

4

AI Builder activity page — for prompt-heavy agents

The AI Builder activity view in the Power Automate portal gives near-real-time per-consumption monitoring of AI tool usage and shows whether a given call drew on AI Builder credits or Copilot Credits. Use it when the PPAC feature breakdown points at AI tools and you need to know which prompt is responsible.

Phase 3 — Optimize: the levers, with the actual deltas

Lever 1 — Route known intents to classic topics

This is the single highest-leverage change available. A classic message node answering "what are your support hours?" costs 1 credit. The same question through generative orchestration is a topic selection (5) plus a generative answer (2) = 7 credits — a 7× delta on your highest-volume traffic. You do not have to abandon generative mode: author classic topics for your top intents inside a generative-orchestration agent and let the orchestrator handle only the genuine long tail.

Lever 2 — Scope knowledge, and switch graph grounding off unless it earns its place

  • Point SharePoint knowledge at the narrowest sub-site that contains the answer, never the root.
  • Stay at or under 25 knowledge sources in generative mode to avoid the extra source-selection model call.
  • Prefer uploaded files for static, controlled content over broad site crawls.
  • Turn off "use information from the web" when web grounding isn't needed.
  • For agents whose users don't hold Microsoft 365 Copilot licenses, tenant graph grounding costs 10 credits per message with no zero-rating. Turn it on deliberately, for the agents that need tenant-wide recall — not as a default.

Lever 3 — Prune and disambiguate tools

Remove tools the agent no longer uses. Then rewrite the descriptions of what remains so they don't overlap — Microsoft's own guidance notes that if multiple topics have similar descriptions, the agent may invoke all of them to answer one question, at 5 credits each. Where intent is unambiguous, use explicit routing in the agent instructions to name the tool directly rather than letting the orchestrator shop around.

Lever 4 — Match the model tier to the job

TierRateUse it for
Basic~0.1 credits / 1K tokensOCR, sentiment, key-phrase extraction, classification, simple text transforms.
Standard~1.5 credits / 1K tokensThe default for most prompt and AI-tool scenarios.
Premium / reasoning~10 credits / 1K tokensGenuine multi-step reasoning only. 100× the basic tier — require a demonstrated need.

For very high token volumes, bringing your own model from Azure AI Foundry can be worth modeling: Copilot Studio then charges only the agent-action rate to invoke it, and the token cost is billed by Foundry under its own (often cheaper at scale) pricing.

Lever 5 — Put the right workload in the right flow engine

Agent flows consume Copilot Credits at 13 per 100 actions. Power Automate cloud flows do not consume Copilot Credits at all — they draw on Power Automate licensing. For flows with very high action counts per run, moving the work to a Power Automate cloud flow removes it from your credit budget entirely; for short flows, the agent flow is usually cheaper. Model both against your actual action counts before deciding. Note that converting an agent flow to a cloud flow is a one-way change.

Lever 6 — Tighten autonomous triggers

Every fired trigger starts billing. Add trigger conditions so the agent only wakes for events it can actually act on, filter at the source (a targeted view or query rather than "all new records"), and confirm run counts in analytics match the number of genuinely actionable events. A trigger that fires on all inbound mail and then decides 90% is irrelevant has already spent the credits.

Lever 7 — Keep pre-production off the meter

Test-panel runs, flow-designer tests and prompt-builder tests are free — so do iteration there rather than against a published agent. Keep dev and sandbox environments on pay-as-you-go and allocate prepaid capacity to production only, so experimentation can never consume the capacity your production agents depend on. Use DLP policies to constrain which connectors agents can reach at all.

Lever 8 — Gate access with authentication

Require authentication on high-cost agents so anonymous traffic can't run up the meter, and so that Microsoft 365 Copilot licensed users are correctly identified for zero-rating — an unauthenticated agent forfeits that benefit entirely. Knowledge-source access follows the user's own Microsoft 365 permissions, so authentication also keeps expensive grounding scoped to people entitled to the content.

Phase 4 — Govern: caps, enforcement, and cadence

Set per-agent consumption limits

In PPAC → Licensing → Copilot Studio → Manage agents you can set a monthly credit cap per agent, configure a notification threshold so admins are alerted before the cap is reached, and have the agent automatically turn off at the cap. This works for both prepaid and pay-as-you-go environments and is the single best guard against one misconfigured agent consuming the tenant's capacity. Pair it with Azure Cost Management budgets (alerts at 80% and 100%) on the Power Platform Account resource for PAYG environments.

Know what happens when you run out

SituationWhat happens
Prepaid consumption reaches 125% of allocationCustom agents are disabled. In-flight conversations finish; new invocations are rejected. Admins get an email and a PPAC notification.
Prepaid consumption reaches 100% (agent flows)New agent flow runs are blocked; the parent agent keeps working for non-flow interactions. Flow makers see a design-time warning.
Per-agent hard cap reachedThat agent alone is turned off; other agents in the environment are unaffected.
Pay-as-you-go environmentNo enforcement. Usage continues and bills to the Azure subscription — which is why PAYG is the right choice for anything business-critical.

When an agent is disabled by enforcement, end users see a generic billing/usage-limit message — not a graceful fallback. If an agent is customer-facing, treat enforcement as an outage scenario and plan the escalation path accordingly.

Enforcement on the GitHub Copilot harness also stops the builders, not just the users. When an environment has no credits available, agents stop responding to requests and makers lose the ability to author with natural language, to preview and test the agent, and to generate or create agent evaluations. Microsoft allows a degree of overage as a grace buffer rather than cutting off instantly, but the recovery path is the same three options: reallocate capacity from elsewhere in the tenant, purchase more, or attach a consumptive/pay-as-you-go meter. Plan for this on shared build environments — one team exhausting the pool halts everyone's authoring, not only production traffic.

Forecasting a new agent before you launch it

Microsoft publishes a free agent usage estimator covering Copilot Studio custom agents and Dynamics 365 agents, with multi-agent aggregation and PDF export for procurement. Microsoft is explicit that it produces informational estimates only and recommends adding a 10–20% buffer.

Do the arithmetic by hand as well — it forces you to confront the stacking:

1. Map the expected turns in a typical session. 2. For each turn, add every event that fires: classic answer +1 generative answer +2 each tool call +5 tenant graph grounding +10 agent flow actions +13 per 100 actions AI tool call tier rate x (tokens / 1000) 3. Credits per session = sum of turn costs 4. Credits per month = credits/session x sessions/day x days 5. Add a 10-20% buffer 6. PAYG cost = credits x $0.01

Worked examples published by Microsoft:

  • Autonomous order-processing agent: 4 action calls × 5 = 20 credits per run.
  • Customer support agent: (4 classic × 1 + 2 generative × 2) × 900 customers/day = 7,200 credits/day.
  • Sales agent with graph grounding, unlicensed users: (4 generative × 2 + 4 graph × 10) × 100 users = 4,800 credits/day — note that grounding alone is 4,000 of those 4,800.
Read that last example again. Graph grounding is 83% of the cost of that agent. Before you tune prompts, shave tools, or downgrade models, check the PPAC feature breakdown — the answer is usually one line item, not a hundred small inefficiencies.

The optimization checklist

Measure

  • Confirmed which harness each agent runs on before diagnosing anything.
  • Pulled the per-agent, per-feature credit breakdown from the PPAC Environments tab.
  • Identified the single largest feature line item before changing anything.
  • Exported session transcripts (28–29 day window) to establish a turns-per-session baseline.
  • Cross-checked abandon rate and resolution rate against credits spent.

Optimize

  • Top-volume intents routed to classic topics rather than generative orchestration.
  • Tenant graph grounding on only where it demonstrably improves answers.
  • Knowledge sources scoped to sub-sites; total kept at or under 25 in generative mode.
  • Web grounding disabled unless required.
  • Unused tools removed; remaining tool descriptions rewritten to be non-overlapping.
  • Premium/reasoning models restricted to cases with a demonstrated need.
  • High-action-count flows evaluated for Power Automate cloud flows instead of agent flows.
  • Autonomous trigger conditions narrowed to genuinely actionable events.
  • Authentication required on high-cost agents.

Govern

  • Per-agent monthly credit caps set, with notification thresholds below the cap.
  • Business-critical agents on pay-as-you-go so enforcement can't take them offline.
  • Prepaid capacity allocated to production; dev/sandbox left on PAYG.
  • Azure Cost Management budget and alerts configured on the Power Platform Account resource.
  • Weekly and monthly review owners named.
  • Estimator re-run each quarter against actual volumes.
