Analyzing Copilot Credit Consumption: Tenant to Agent

A complete map of where Copilot Credit consumption is reported and how to read it at every scope — tenant, environment, agent across environments, agents within an environment, and functionality within a single agent. Compiled from public Microsoft documentation · September 2026.

The one thing to remember: there is no single screen that answers every cost question. Consumption is reported at five different scopes in two different products, and each scope answers a different question. Analysis means knowing which screen answers the question you are actually asking, and knowing that the number on it is billed credits, nonbillable credits, or both.

1. Billed vs nonbillable: the vocabulary

Every consumption grid in the Power Platform admin center splits credits into billed and nonbillable. Reading a cost report without understanding that split is the single most common source of wrong conclusions, in both directions: teams panic about volume that costs nothing, or they budget against a number that excludes the activity that will cost them the most next quarter.

Billed credits

What it means

Consumption that actually draws down capacity. A billed credit either deducts from a prepaid Copilot Credit pack allocated to the environment, or meters against a pay-as-you-go billing plan linked to an Azure subscription.

Why it matters

Billed credits are the only number that moves you toward overage. They drive enforcement, they are what an agent-level monthly limit counts, and they are what appears on the invoice.

Counts against allocation Triggers enforcement Appears on the bill
Nonbillable credits

What it means

Activity that is metered and reported in the same units, but does not deduct from prepaid capacity and does not meter to pay-as-you-go. It is usage that is covered by an entitlement you already hold, or that Microsoft explicitly excludes from billing.

Why it matters

Nonbillable credits are your true usage signal. They tell you how heavily an agent is really used, and they quantify the exposure you would take on if the entitlement covering them ever changed.

Real usage signal No capacity draw Latent exposure

What makes consumption nonbillable

SituationWhy it is not billed
A Microsoft 365 Copilot licensed user interacts with an agent in an employee-facing scenario, under their own authenticated identity Employee-facing (business-to-employee) use of Copilot Studio agents and the tools those agents invoke is included in the Microsoft 365 Copilot user subscription license, subject to fair-use limits. Every line in the rate card shows No charge for this case.
Agents created inside the Teams environment using Copilot Studio for Microsoft Teams These agents do not consume Copilot Credits at all, regardless of who uses them. Note the inverse: an agent built in standalone Copilot Studio and merely published to the Teams channel does consume credits.
Messages in the embedded test chat while authoring Test chat conversations do not count as billed consumption.
Agent flow test runs from the flow designer or the agent test chat Test runs do not consume agent flow action capacity and are never blocked by agent flow enforcement.
Generative answers in an agent created in Agent Builder in Microsoft 365, where the response does not use tenant graph grounding This specific combination is exempted from the generative answer charge.

What is never nonbillable, whatever the license

  • Computer-Using Agent (CUA) activity. Billed at the agent action rate and explicitly excluded from the Microsoft 365 Copilot user subscription license inclusion.
  • Agent flows triggered by anything other than "When an agent calls the flow". The no-charge inclusion for Microsoft 365 Copilot licensed users applies only to that trigger. A scheduled or event-driven agent flow bills at the standard rate.
  • Bring-your-own-model configurations, including Microsoft Foundry models. These are billed separately and do not appear in the Copilot Credit meters at all, which means a Copilot Credit report can be flat while spend is rising elsewhere.
  • Preview features. Features in preview charge at the published rate and count against purchased capacity.
The proactive greeting trap. If an agent is triggered to be ready for a conversation, it consumes credits as a classic answer whether or not a greeting is sent and whether or not the user ever replies. In analytics that same session is categorized as unengaged. Billing follows the agent's activity; engagement follows the user's behavior. The two numbers are not meant to match, and chasing the gap between them wastes a lot of time.

Three more distinctions worth fixing in your head

TermWhat it actually measures
Copilot CreditThe unit of consumption. One credit represents one request to Copilot that prompts a response or action, but different features consume different numbers of credits per occurrence.
Billed sessionThe legacy unit from the pre-2024 Power Virtual Agents license. Still reported for organizations on that plan. If a tenant switched mid-period, both billed sessions and Copilot Credits appear for the overlapping range.
Total / engaged sessionAnalytics metrics describing how effectively an agent resolved a user's question. Independent of billing. Never reconcile these against billed credits.

2. The five scopes and what each answers

Consumption reporting lives in two products. Everything at tenant, environment and cross-environment agent scope is in the Power Platform admin center. Everything about a single agent's internal behavior is in Copilot Studio itself, on the agent's Monitor page. Match the question to the scope before you open anything.

ScopeThe question it answersWhere it lives
1. Tenant Are we in aggregate within capacity, and is the trend going the wrong way? Admin center → Licensing > Copilot Studio > Summary
2. Environment Which environments are consuming, which are in overage, and is capacity allocated where the demand actually is? Admin center → Licensing > Copilot Studio > Environments
3. Agents across environments Which agents in the whole tenant are the biggest consumers, and which are near or over a limit? Admin center → Summary > Manage Agents
4. Agents within an environment Inside this one environment, which agents and which features are consuming, and how much of it is billed? Admin center → Environments > [environment] > Copilot credit consumption details
5. Functionality within an agent For this agent, what kind of activity is driving the cost, and how is it trending against its limit? Copilot Studio → agent → Monitor
A note on harnesses. Copilot Studio is a multi-harness platform, and the admin center gives a unified capacity view across the Copilot Chat, standard and GitHub Copilot harnesses. The agent-level Monitor page described in Scope 5 applies to the standard harness. GitHub Copilot harness agents are metered and governed differently, so verify which harness an agent is on before you interpret an agent-level number.

The layer above all five: cross-product reporting

Every scope in the table reports Copilot Studio in isolation. None of them answers the question a CFO actually asks, which is what the whole AI estate costs and what next year looks like. Consumption Central for Microsoft Copilot is a Microsoft-built, open-source Power BI template that fills that gap: fifteen pages covering consumption, cost, optimization and forecast for each of Copilot Cowork / Work IQ, Copilot Studio, GitHub Copilot and Azure AI Foundry, plus a combined overview.

  • One product is enough. Load whatever data you have; pages for products you skip come up empty and nothing breaks.
  • Three setup paths. Local CSV in roughly ten minutes, Fabric for weekly unattended refresh, or Viva Direct for Cowork data with no file exports. Start with Local CSV to find out whether the numbers are worth automating before automating them.
  • Set the credit price. The template defaults to list price at $0.01 per credit. Change it only if the agreement differs; this is the input that makes the cost pages credible.
  • It demos with no tenant data. Synthetic sample data ships with every path.

Two caveats to state before anyone builds a process on it: it is community-supported through GitHub issues rather than Microsoft support channels, and the identified Viva Insights variant processes personal data, which needs a privacy review in some regions. Use it as the trend and forecast layer; the admin center stays authoritative for the current month.

3. Scope 1 — Tenant-wide consumption

Start here for any budgeting, renewal or true-up conversation. This is the only view that shows prepaid and pay-as-you-go side by side.

1

Open the summary

Sign in to the Power Platform admin center, select Licensing in the navigation pane, choose Copilot Studio under Products, then the Summary tab.

2

Read the capacity summary cards

  • Pay-as-you-go credits — the number of active billing plans carrying the Copilot Studio meter, and month-to-date credits billed to them. A billing plan groups one or more environments and bills their usage to an Azure subscription.
  • Prepaid capacity — units purchased, assigned and consumed. These may be Copilot Credit units or legacy session-based units, each with its own management link.
3

Work through the Copilot Credits capacity tab

  • Capacity consumption by product — a product-level split of units deducted from prepaid packs versus pay-as-you-go. Credits consumed by Microsoft 365 Copilot Chat appear under that product rather than being mixed into custom agent usage.
  • Total capacity consumption trend — daily consumption over the past three months. This is your seasonality and step-change detector.
  • Copilot credit usage by environment — the top environments by usage. Use it purely to pick your next click; do the real environment work in Scope 2.

For planning horizons longer than a quarter, the consumption monitoring views also carry month-to-date, the last two full months at daily granularity, and monthly totals for the past twelve months. That twelve-month series is the right input for a renewal or a pre-purchase sizing exercise.

4. Scope 2 — Consumption by environment

The Environments tab is where allocation decisions get made. It reports, per environment, the credits deducted from prepaid capacity, the units billed under pay-as-you-go, and the environment's status.

Navigate to Licensing > Copilot Studio > Environments, select Select environment, then choose the environment from the pane. To see credits consumed by Microsoft 365 Copilot Chat, choose the Microsoft 365 Copilot Chat entry on that selection page.

The four things this view tells you

SignalHow to act on it
Within capacity or in overageOverage is the trigger for reallocation, purchase, or enabling a pay-as-you-go meter. Enforcement fires at 125% of prepaid capacity, at which point custom agents are disabled.
Whether capacity is allocated at allAn environment with no allocation draws against the remaining tenant pool. Several unallocated environments sharing one pool is the classic cause of an unrelated team's agents being disabled.
Whether pay-as-you-go is in useAn environment with a linked billing plan is insulated from tenant overage. Once its own allocation is exhausted, the meter simply takes over.
Prepaid vs pay-as-you-go splitA high pay-as-you-go share on a stable, predictable workload is usually a signal to move that workload onto prepaid capacity.
Allocation is protective, not just administrative. An environment with its own allocation keeps consuming from that allocation even while the tenant as a whole sits in overage. Environments with no allocation share the residual tenant pool and are the first to be enforced. Allocating capacity to a business-critical environment is the cheapest insurance available.

5. Scope 3 — Agents across environments

This is the view most people are looking for when they ask "which agent is costing us the most?" and it is the least discoverable. It is not on the Environments tab. From Licensing > Copilot Studio > Summary, select Manage Agents.

The Agents page lists every Copilot Studio agent across the tenant that incurs billing charges. For each agent you get:

  • Month-to-date billed credits
  • The environment the agent belongs to
  • Any configured monthly Copilot Credit limit
  • A status of Within limit, Nearing limit, or Over limit
  • Search across agents, and the ability to turn an agent off

Using it as an analysis surface, not just a control panel

Sorted by month-to-date billed credits, this page gives you the tenant-wide cost ranking in one screen. Three readings are worth making every month:

  1. Concentration. If two or three agents account for most of the tenant's billed credits, optimization effort belongs on those agents and nowhere else.
  2. Environment mismatch. An agent consuming heavily inside an environment with little or no allocation is an enforcement incident waiting to happen.
  3. Unbudgeted growth. Any agent with no configured limit and a rising month-to-date figure is, by definition, uncapped exposure.

Monthly limits can be set per agent from this page whether the environment uses prepaid capacity or pay-as-you-go. In a prepaid environment the agent must stay within the allocated pool; in a pay-as-you-go environment you can set any limit and usage bills accordingly. Two guardrails attach to a limit:

  • Notifications — environment-level and tenant-level admins are alerted as an agent approaches its limit.
  • Hard stop — the agent is turned off automatically when it reaches the limit.

6. Scope 4 — Agents within one environment

Once an environment is identified as a hotspot, drill into it. On the environment view, the Copilot Credits capacity tab carries two cards:

Capacity consumption by product

A product-focused summary for this environment: units drawn from prepaid capacity packs and units metered to pay-as-you-go. Use it to confirm which billing mechanism is actually absorbing this environment's usage.

Copilot credit consumption details

The analytical heart of the whole exercise. A grid of the agents consuming capacity in this environment, each with its associated product, the feature name driving the consumption, and the count of billed versus nonbillable credits.

How to read the consumption details grid

Because the grid carries a feature name per row, it is simultaneously an agent-level and a feature-level view. Four patterns are worth recognizing on sight:

PatternWhat it usually means
High nonbillable, low billed A healthy employee-facing agent used mostly by Microsoft 365 Copilot licensed staff. Volume is real, cost is not. Do not optimize this for cost; optimize it for quality.
High billed, low nonbillable Either a genuinely external or customer-facing agent, or an internal agent whose users are not Microsoft 365 Copilot licensed, or one running under a service identity rather than the user's identity. The last case is a fixable design problem, not a licensing problem.
A single feature name dominating The clearest optimization target you will find. Tenant graph grounding at 10 credits and premium AI tools at 100 credits per 10 responses dominate quickly once they are switched on.
Agent flow actions present and growing Worth isolating. When prepaid capacity is exhausted, agent flow enforcement blocks new flow runs while the parent agent keeps working for non-flow interactions. Flow authors also see a design-time warning in the Copilot Studio designer. This produces a partially broken agent rather than an obviously dead one, which is much harder to triage from a user report.

7. Scope 5 — Consumption by functionality

To attribute an individual agent's cost to the kind of work it is doing, leave the admin center and open the agent in Copilot Studio, then go to Monitor. Set the time period with the dropdown at the top of the page; select See billing for detail.

1

Overview panel

Total billed Copilot Credits for the selected period. If the organization is on the legacy plan, this shows billed sessions instead, and shows both if the tenant switched mid-period.

2

Billing trend

Billed credits over the selected period. Hover any point for the exact figure. Read this against release dates: a step change that lines up with a publish is a design regression, while a smooth ramp is adoption.

3

Cost distribution

The functionality breakdown, and the reason this page exists. It shows which kinds of activity count toward the agent's credit usage, using total credits per activity. Because each activity type consumes a different number of credits per occurrence, the tallest column is not necessarily the most frequent activity — it is the most expensive one in aggregate.

4

Monthly credit limit

A stacked bar of credits used against credits remaining for the calendar month. Hover the segments for used and remaining figures. This is the fastest way to see whether an agent is within, near, or exceeding the budget set for it in Scope 3.

Read cost distribution as credits, not as events. A column representing 200 credits could be 200 classic answers, 100 generative answers, 40 agent actions, or 20 tenant graph grounded messages. Convert to event counts using the rate card below before drawing any conclusion about user behavior.

8. The rate card behind the functionality view

Cost distribution is uninterpretable without the rates. These apply to the language models Copilot Studio provides and exclude bring-your-own-model configurations, which bill separately.

Agent featureBilling rateMicrosoft 365 Copilot licensed user
Classic answer1 creditNo charge
Generative answer2 creditsNo charge
Agent action (includes Computer-Using Agents)5 creditsNo charge (CUA excluded)
Tenant graph grounding for messages10 creditsNo charge
Agent flow actions, per 100 actions13 creditsNo charge (only for the "When an agent calls the flow" trigger)
Text and generative AI tools (basic), per 10 responses1 creditNo charge
Text and generative AI tools (standard), per 10 responses15 creditsNo charge
Text and generative AI tools (premium), per 10 responses100 creditsNo charge
Content processing tools, per page8 creditsNo charge
Classic voice, classic orchestration, per minute10 creditsCore agent activity included
Generative AI voice, per minute35 creditsCore agent activity included
Premium generative AI voice, per minute75 creditsCore agent activity included

The stacking rule

A single interaction can use several feature types at once, and the charges add. A tenant graph grounded generative answer costs 12 credits: 10 for the grounding and 2 for the generative answer.

Reasoning models stack in the same way, across two meters. The feature rate covers the core action and always applies. The text and generative AI tools (premium) rate then applies on top for the reasoning model's token usage, at 10 credits per 1,000 tokens.

Total cost = feature rate for the operation + text and generative AI tools (premium) for reasoning token usage Example: a generative answer produced by a reasoning model = 2 credits + premium tool credits per 1,000 tokens

9. A worked read of a cost distribution

Suppose an agent's Monitor page shows 30 days of activity and a cost distribution roughly as follows.

ActivityCreditsShareImplied volume
Tenant graph grounding42,00064%4,200 grounded messages
Generative answers16,80026%8,400 answers
Agent actions5,0008%1,000 actions
Classic answers1,4002%1,400 answers

The reading is not "grounding is the biggest activity". By volume, generative answers are twice as frequent. Grounding dominates the bill because it costs five times as much per occurrence, and because it fired on only half the answers, which tells you it is conditional rather than universal. Three concrete questions follow directly from that:

  1. Do the grounded answers demonstrably outperform the ungrounded ones? If quality is comparable, grounding is buying 64% of the bill for nothing.
  2. Are the 1,000 agent actions genuine task completions, or are they topic transitions and triggers inflating the count? Both bill at the agent action rate.
  3. Cross-check the billed versus nonbillable split in Scope 4. If most of this traffic is Microsoft 365 Copilot licensed staff, the real invoice impact may be a fraction of the credit totals shown here.

10. Data freshness and reconciliation traps

TrapWhat to do about it
Analytics lag a few hoursThe Monitor page takes a few hours to reflect new billed credits. Never diagnose a spike on same-day data.
Admin center data aggregates dailyTenant consumption aggregates daily and can be delayed. The consumption bar shows all known consumption as of the Last updated timestamp in its tooltip. Quote that timestamp in any report you circulate.
Capacity resets on the first of the monthUsage is counted monthly starting on day one, not on your license anniversary. Comparisons must be month-aligned.
Unused capacity does not carry overLeftover capacity expires. Consistent under-consumption is a sizing problem, not a saving.
Billed sessions are per-agent onlyFor organizations still on the legacy session model, there is no tenant-level billed session total. Aggregate agent by agent.
Credit reports exclude bring-your-own-model spendFoundry and other external models bill separately. A flat credit report does not mean flat AI spend.
Power Automate cloud flows are not Copilot CreditsCloud flows use Power Automate licensing and are outside Copilot Studio billing and enforcement entirely. Only agent flows managed in Copilot Studio consume credits.

11. An analysis cadence that works

Weekly — 10 minutes
  • Manage Agents page, sorted by month-to-date billed credits
  • Anything at Nearing limit or Over limit
  • Any new agent appearing in the list for the first time
Monthly — 45 minutes
  • Tenant trend across the three-month daily series
  • Environment table: allocation versus actual consumption
  • Consumption details grid for the top two environments
  • Monitor cost distribution for the top three agents
Quarterly
  • Twelve-month monthly series for sizing and renewal
  • Reallocate capacity toward where demand actually landed
  • Reassess prepaid versus pay-as-you-go per environment
  • Re-baseline every agent-level monthly limit
On every agent release
  • Compare cost distribution before and after publish
  • Confirm no new grounding or premium tool was enabled silently
  • Check the billing trend for a step change at the release date

13. Analysis checklist

  • I know whether the number I am looking at is billed, nonbillable, or both
  • I know which harness the agent in question runs on
  • I have checked the tenant summary for prepaid and pay-as-you-go together
  • I have identified which environments have allocation and which draw from the tenant pool
  • I have ranked agents tenant-wide from the Manage Agents page
  • I have opened the consumption details grid for the top consuming environment
  • I have read the top agent's cost distribution and converted credits to event counts
  • I have separated agent flow action consumption from the rest
  • I have confirmed no reasoning model or premium tool was enabled without a decision
  • I have noted the Last updated timestamp on any figure I am circulating
  • I have checked whether bring-your-own-model spend exists outside these meters
  • Every business-critical environment has its own allocation
  • Every agent with material consumption has a monthly limit, notifications, and a considered hard-stop setting
